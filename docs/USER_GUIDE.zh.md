# COBOT MAGIC 工作台使用手册

Yang Taige · Ye Hanzhi | Emerge Robotics

## 范围与发布状态

这是一个持续开发中的研究工作台。当前发布包含 Windows 便携 SSH 客户端、管理服务、实验室操作与设备源码、FP32/BF16 推理适配、V2 与共享执行器源码快照、离线检查和打包工具。客户端可直接启动；实验室源码仍需按安装配置环境。硬件工作流依赖已安装的任务与设备后台。

当前便携包面向操作员连接已经配置好的 GPU 主机。完整的 COBOT MAGIC 首次安装仍在开发中。

作者为 **Yang Taige、Ye Hanzhi**，组织为 **Emerge Robotics**，隶属于 **HKU Faculty of Engineering**、**Tam Wing Fam Innovation Wing**。

## 安装操作端客户端

- 下载 GitHub Release 的 Windows SDK，解压 ZIP，双击 `Start-Workbench.cmd`。内置 Python 与 OpenSSH，离线回放无需机器人或账号。

- 向管理员申请自己的 SSH 授权，并通过可信渠道核对主机指纹。

- 在 SDK 起始页填写自己的 SSH 别名（或 user@host）、可选的 SSH 配置路径及服务器端口 8910，点击连接。SDK 保存本地连接配置，不携带凭据。

- 通过 `ssh your-gpu-host hostname` 核实目标主机。

- 启动 `client/Start-Workstation.cmd`，或执行下方命令。打开输出的本地网址，检查服务和设备状态。

```
python client/gateway.py --config client/client.local.json
```

SDK 起始页使用 8926，实时客户端默认 8876，便于与旧安装并存。源码 CLI 默认 8875；远端管理端口为 8910。在私有配置里选择空闲的本地端口，客户端会转接所需 Host/Origin 字段。

Windows 启动日志在 `%LOCALAPPDATA%/AgileXClient`。SSH 失败、服务不兼容或端口占用会显示为连接问题。

## 配置 GPU 主机

GPU 主机管理软件发布、模型服务和任务队列。在独立副本中开发，启用经过核验的固定版本。管理服务监听本机回环地址，并连接已安装的任务后台。

```
python -B -m server.main --port 8910 --legacy-origin http://127.0.0.1:8873 --web-root ./web
```

该命令运行开发版管理层。固定版本需通过对应启动选项提供已核验的发布清单。接入前阅读源码中的 `docs/server-contract.md` 和 `docs/recovery.md`。

- `GET /platform/health` 返回管理层版本与完整性。

- `GET /platform/status` 返回运行及验证状态。

- `/workbench/` 提供已连接的操作界面。

- `/api/state` 返回任务后台状态。

完整实验室安装还包括设备后台与模型/控制器环境，其完整自动安装仍在开发。地址、SSH 授权和物理 USB 身份使用私有配置。

## 试验前检查

- 读回 GPU 主机与机器人计算机的真实主机名和启动周期。

- 检查已登记 CAN 适配器、波特率、控制模式和新鲜关节/夹爪反馈。

- 通过现有共享生产者查看所需相机画面。

- 选择物理 USB 盘，核对身份、可写挂载和剩余空间。

- 检查活动任务、录制/保存状态、执行 owner 与 STOP 状态。

- 确认检查点、提示词、控制路线和匹配的验收记录。

人工确认属于本次试验。明确点击执行提供操作员声明，后台同时核验可测条件。模型、设备或软件发生变化后可能需要重新检查。

## 机械臂操作范围

连接页四张卡分别对应 LE 左执行臂、RE 右执行臂、LT 左示教臂、RT 右示教臂。点击 BASE 可查看底盘详情。每张卡分别显示设备反馈和可用操作。电脑接管和电机失能在 RE 卡片上申请。原厂高跟随、待机和受支撑复位在右执行臂维护菜单内，切换结果以设备反馈为准。

运动测试的全部六零位在提交时固定已登记并回报 CAN / MOVEJ 的目标臂，条件满足后依次回零。DAgger 按当前模型任务身份交接。顶部和部署页的停止入口停止发送新目标，录制页的结束入口保存当前片段。

## 运行一次试验

### 采集示教

- 进入经检查的主从遥操作模式。

- 确认任务标签、相机画面和录制位置。

- 开始录制，示教任务并观察反馈。

- 停止试验，等待录制完成并复核 episode。

### 运行策略

- 在同一区域选择部署路线、检查点、提示词和时长。

- 加载所选模型，完成该路线需要的无运动检查。

- 检查真实起始姿态、物体位置和控制归属。

- 明确启动，观察图像、反馈与运行消息。

- 需要时使用操作员停止入口，结束后核对保存的数据并标注真实操作结果。

当前策略实验主要是右臂 pick-and-place。每个检查点、提示词与控制器分别评估，软件完成和真实任务成功分别记录。

### 手动目标

运动页使用六个关节角度与毫米单位的夹爪开口；模型/控制器内部使用弧度和米。检查坐标映射与当前范围，移动到显示零位与重设编码器零点属于不同操作。

现有手动夹爪路径与活动录制/部署互斥。连续语言模型动作实验需要先完成经过检查的执行与录制协同。

## 控制路线与 DAgger

现有工作台支持 FP32 + RTC、BF16 轨迹优化和实验性 Realtime-VLA V2 路线。每条路线有自己的模型身份、时序和验收要求，精确设置从有效运行版本读取。

Realtime-VLA V2 探索时间参数化参考与本地模型预测控制。参考覆盖、暂停请求处理和人工调速都进入实验记录。

DAgger 正在开发。计划闭环为策略运行、明确专家介入、纠正标签对齐、数据聚合、再训练及新检查点评估。观察、策略提案、专家纠正和发送命令分别保存。

新算法通过版本化适配器和明确路线接入，上机前检查 owner、STOP、单位、范围、录制和模型实例匹配。

## 录制与回放

原始试验数据写入当轮选定并核验的机器人 USB 盘。写入者结束前保持同一物理存储身份，随后检查最终持久化回执并读回数据流。

- 保存带时间戳的视频、实测关节/夹爪、预测与实际目标。

- 保存任务、检查点、提示词、控制设置和源码版本。

- 原始预测与转换或限幅后的输出分别保留。

- 保留失败和中断试验的真实状态。

- 用清单与哈希关联图像、元数据和命令。

大图像可以独立校验附件保存，元数据仍有容量限制。高频数据复用现有生产者和有界后台写入器。

## 故障排查

- **SSH 超时。**检查供电、网口载波、当前地址和路由，保留主机指纹校验。

- **页面或反馈过期。**提交新任务前读取当前后台响应与数据年龄。

- **Acceptance is stale。**检查源码版本、启动周期、USB 和模型实例，按既定流程重建受影响绑定。

- **STOP 锁存。**检查会话后明确恢复。软件停止阻止新目标，已接受目标可能继续完成。

- **参考覆盖不足。**查看时间记录并保留已接受轨迹，恢复前检查完整 RTC 前缀。

- **录制不完整。**保留失败回执，检查 USB 身份和最终写入，解决记录器失败。

命令超时按结果未知处理。先查询原任务并核对 owner，恢复连接不得重放运动请求。

## 源码与发布流程

仓库按 `client/`、`server/`、`web/`、`site/`、`docs/`、`tools/` 和 `tests/` 组织。公开项目页位于 `site/`，操作管理界面位于 `web/`。

在分支中开发，完成相关检查后提交 Git。可见改动附简要说明和截图。构建并核验固定包，在空闲安装上部署，随后读回实际运行版本。

```
python -B -m unittest discover -s tests -p "test_*.py" -v
node --test tests/test_ui*.mjs
python -B tools/release.py build --package source --output dist/source.zip
python -B tools/release.py verify dist/source.zip
```

版本库使用示例配置。个人地址、凭据、原始录像、权重和运行回执排除在公开历史之外。当前 Alpha 提供面向已配置实验室系统的管理层/客户端基础，便携机器人安装仍在推进。
